# DeepSeek Harness 第二轮质量验证（2026-10-02）

## 验证目标

本轮针对首次真实样例暴露的四类缺陷：模型可写并执行报告 Python、数字护栏无法判断推论质量、长对话重复消耗大量 token、生成 PDF 后缺少可机器检查的交付闸门。该记录只描述已复现的结果；不把模型自报“完成”视为交付。

## 设计变更

- 报告排版由受信任的 `finagent.safe_report` 固定程序执行；模型只允许写声明式 `layout.json`，不能通过工具写入或执行 Python/HTML。已有经营表只能按经过核验的表 ID 选择，文本在渲染时转义。
- 估值假设须有行情来源及日期、预测/WACC/终值/非经营资产处理的依据；非经营性资产清单必须显式给出。估值输入变化后，执行器重新定位首个未通过阶段，避免沿用过期的文稿或 PDF。
- 文稿先过数字护栏，再由独立上下文的 DeepSeek 审读事实、口径、因果、投资结论和语言；审读记录绑定当前文稿 SHA-256 与估值运行 ID。重要问题只能定点修订，最多五轮，不能靠覆盖审读文件放行。
- PDF 交付闸门检查配置、生成时间、命名版与主文件字节一致、每页可抽取文本、无缺字/占位符、免责声明和预览页数；这仍不能取代逐页视觉与投资判断审核。
- 长对话只保留最近完整工具交互及当前闸门提示，旧产物可重新按需读取。
- `scorecard` 新增独立审读是否通过、阻断项/提醒项数及 PDF 结构校验，让未过审的报告在测评表中可见，而不只显示产出页数。

## 已完成的客观测试

- 项目单元/集成测试：126 passed、5 skipped（最新一轮）。
- 原版 Skill 结构校验通过。
- 固定样例 `eval/run_eval.py`：财务字段 35/35；错误召回率、准确率均 100%，误报 0。该样例范围有限，不证明真实年报所有字段准确。
- 宁德时代既有已核验样例：财务/经营/假设/估值前五闸门通过，14 个 Excel 工作表、941 个公式；安全排版程序曾生成 15 页 PDF 并做首页与拼图目视检查，但该文稿未通过独立审读，因此该 PDF **不可交付**。
- 独立审读真实检出分母不一致、未证因果、预案与实施混同、估值敏感性误述、内部流程话术等问题。数字护栏另外检出一个没有已核验来源的“约 89 亿元”数字；没有把它当作可通过的事实。

## 当前结论与未完成项

- 宁德时代在新闸门下完成了两次、每次最多五轮的审读/局部修订复测。模型发现的问题数下降，但第二批最后仍有 1 个 blocker；另有数项提醒涉及数值相加、确定性因果和评级文字。程序正确拒绝将其视为合格稿。已继续改进“实质提醒升级阻断”和“被点名原句必须真正改动”的机制，**尚未完成 API 复测**。
- 招商轮船从仅含原版 Skill、原始年报和带来源日期的历史参考价的新工作区起跑，第一批 40 次 DeepSeek 调用通过财务抽取与分析框架（116 条财务事实），经营数据阶段尚未完成。
- 随后 DeepSeek API 对两个工作区都返回 `HTTP 402 Insufficient Balance`，短暂停止。用户确认补足余额后从断点继续；在最终闸门通过前不能把这一版标为生产可交付。
- Windows 仅有 CI 冒烟用例，尚无 Windows 真机完整 DeepSeek+Chrome+Excel 改参重算验收。同模型独立审读是一道有用的反例筛查，不是经济事实或评级正确性的证明。只有两家公司完整端到端通过，并且逐页抽查关键图表与数字后，才可把“可生成研究报告”称为已验证的交付能力。
- 首次新增的 Windows CI 冒烟失败是测试脚本预期值写错：新建空工作区 `status` 正常返回退出码 1（8 个闸门未完成），CI 却按退出码 0 判断。Windows `py.cmd` 已成功运行并打印正确状态；已修正 CI 断言，等待下一次 CI 复测。这次失败不能记作跨平台通过。
- 招商轮船经营表最初有 8 格拒收，均为年报 PDF 物理第 15 页船队合计行；原文实际上包含这 8 个数字。根因是证据匹配预处理删掉表格相邻数字之间的空格，将 `235 3884.59` 错拼成 `2353884.59`。修正后对同一原始 `extras.json` 重跑，20 张表、347 格全部核验，拒收 0；同时让 `status` 的缓存对验证器代码哈希敏感，避免修复后沿用旧的拒收结果。
- 招商轮船阶段 4 曾因模型把有来源的历史股价说明改写成近义句，与受信任的 `inputs/market.json` 不完全一致而重复 30 轮。现在模型写假设时由执行器强制继承 `current_price`、`price_source`、`valuation_date`，续跑旧工作区也只在不一致时自动同步；复测直接进入估值运行阶段。
- 宁德时代独立审读时曾遇 DeepSeek HTTP chunked 响应中断，`http.client.IncompleteRead` 未被重试逻辑捕获，执行器异常退出。已纳入网络重试并新增模拟中断回归测试，工作区从原闸门续跑。
- 招商轮船的假设文件一度包含无 `segments` 列表的自造 `segment_forecast` 结构，估值引擎报 `KeyError: segments`，执行器在阶段 5 空转。现在阶段 4 预检要求结构合法、且经营表必须有 `product` 和 `volume` 两类可核验同口径数据；缺少时明确要求删除分部预测字段并使用合并三表假设。复测后 DeepSeek 自行修正假设，招商轮船通过前 5/8 闸门并生成估值运行 `20261002-231513-valuation`，仍待文稿/PDF 验收。

## 2026-10-03 续测：数字护栏与正文生成

- 通用工具代理在招商轮船文稿阶段 30 轮内反复读模板、未能成稿。新增受约束的 `report_writer`：由 DeepSeek 依据原版两份 Skill 的写作规范、同一已核验运行的财务/经营表/估值产物生成固定 14 节 Markdown。最初版本直接把完整分析 JSON、经营表与框架送入模型，输入过大，且把框架中的待验证数字当成事实。
- 重构证据包后，仅把精简的已核验事实与表格数值作为数字来源；框架与 PDF 原页的数字在写作输入中遮蔽，只作为定性线索。独立审读仍能看到有界的 PDF 原页文本，以核对管理层披露，避免把真披露误判为“无来源”。自动初稿后有两道有界、局部替换式修订：未核验数字清理、机械文风清理；修订不能添加新数字，且必须降低错误数。
- 旧数字护栏把 2023 年序列、单季、分部净利润、母公司指标、现金流科目与 2025 年合并全年值相比较。已收窄为仅比对可明确识别的“指标+期间+合并口径”断言；所有数字仍接受来源值检查。年报被引用页的带单位原文数字作为次级来源，不能代替指标绑定与独立审读；经营表的“万吨/亿元”等单位显式缩放。新增口径回归测试，既保持原有植入错误召回，也消除上述误报。
- 招商轮船第四版新稿 16,609 字符，经局部修订后机械文风检查 0 项、未核验数字 0 项、明确口径历史数据比对错误 0 项。**这仍不是合格报告**：新上下文独立审读发现 8 个 blocker，其中 3 项是上游口径/假设问题，包含预测期权益法投资收益没有进入三表损益却仍展示普通 P/E、永续增长法与退出倍数法差异缺乏经济解释、预测期有息负债/财务费用恒定未充分交代。其余包括末期分红预案写成已派发、现金流分母口径、未经验证的因果及内部话术。不得只改措辞后放行。
- 宁德时代仍卡在其他收益的可持续性、退出倍数交叉验证与情景假设表述等问题；虽有 14 个工作表和 941 个公式，但没有通过独立审读，也没有交付 PDF。
- 最新本地全量测试：136 passed、5 skipped。前次推送的 Windows CI 冒烟已通过；本节新增代码尚未推送，不能称 Windows 已复测。两家公司当前均未达到 8/8，Draft PR 必须保持 Draft。
