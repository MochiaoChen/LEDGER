# DeepSeek Harness 第二轮质量验证（2026-10-02）

## 验证目标

本轮针对首次真实样例暴露的四类缺陷：模型可写并执行报告 Python、数字护栏无法判断推论质量、长对话重复消耗大量 token、生成 PDF 后缺少可机器检查的交付闸门。该记录只描述已复现的结果；不把模型自报“完成”视为交付。

## 设计变更

- 报告排版由受信任的 `finagent.safe_report` 固定程序执行；模型只允许写声明式 `layout.json`，不能通过工具写入或执行 Python/HTML。已有经营表只能按经过核验的表 ID 选择，文本在渲染时转义。
- 估值假设须有行情来源及日期、预测/WACC/终值/非经营资产处理的依据；非经营性资产清单必须显式给出。估值输入变化后，执行器重新定位首个未通过阶段，避免沿用过期的文稿或 PDF。
- 文稿先过数字护栏，再由独立上下文的 DeepSeek 审读事实、口径、因果、投资结论和语言；审读记录绑定当前文稿 SHA-256 与估值运行 ID。重要问题只能定点修订，最多五轮，不能靠覆盖审读文件放行。
- PDF 交付闸门检查配置、生成时间、命名版与主文件字节一致、每页可抽取文本、无缺字/占位符、免责声明和预览页数；这仍不能取代逐页视觉与投资判断审核。
- 长对话只保留最近完整工具交互及当前闸门提示，旧产物可重新按需读取。
- `scorecard` 新增独立审读是否通过、阻断项/提醒项数及 PDF 结构校验，让未过审的报告在测评表中可见，而不只显示产出页数。

## 已完成的客观测试

- 项目单元/集成测试：122 passed、5 skipped。
- 原版 Skill 结构校验通过。
- 固定样例 `eval/run_eval.py`：财务字段 35/35；错误召回率、准确率均 100%，误报 0。该样例范围有限，不证明真实年报所有字段准确。
- 宁德时代既有已核验样例：财务/经营/假设/估值前五闸门通过，14 个 Excel 工作表、941 个公式；安全排版程序曾生成 15 页 PDF 并做首页与拼图目视检查，但该文稿未通过独立审读，因此该 PDF **不可交付**。
- 独立审读真实检出分母不一致、未证因果、预案与实施混同、估值敏感性误述、内部流程话术等问题。数字护栏另外检出一个没有已核验来源的“约 89 亿元”数字；没有把它当作可通过的事实。

## 当前结论与未完成项

- 宁德时代在新闸门下完成了两次、每次最多五轮的审读/局部修订复测。模型发现的问题数下降，但第二批最后仍有 1 个 blocker；另有数项提醒涉及数值相加、确定性因果和评级文字。程序正确拒绝将其视为合格稿。已继续改进“实质提醒升级阻断”和“被点名原句必须真正改动”的机制，**尚未完成 API 复测**。
- 招商轮船从仅含原版 Skill、原始年报和带来源日期的历史参考价的新工作区起跑，第一批 40 次 DeepSeek 调用通过财务抽取与分析框架（116 条财务事实），经营数据阶段尚未完成。
- 随后 DeepSeek API 对两个工作区都返回 `HTTP 402 Insufficient Balance`，短暂停止。用户确认补足余额后从断点继续；在最终闸门通过前不能把这一版标为生产可交付。
- Windows 仅有 CI 冒烟用例，尚无 Windows 真机完整 DeepSeek+Chrome+Excel 改参重算验收。同模型独立审读是一道有用的反例筛查，不是经济事实或评级正确性的证明。只有两家公司完整端到端通过，并且逐页抽查关键图表与数字后，才可把“可生成研究报告”称为已验证的交付能力。
- 首次新增的 Windows CI 冒烟失败是测试脚本预期值写错：新建空工作区 `status` 正常返回退出码 1（8 个闸门未完成），CI 却按退出码 0 判断。Windows `py.cmd` 已成功运行并打印正确状态；已修正 CI 断言，等待下一次 CI 复测。这次失败不能记作跨平台通过。
