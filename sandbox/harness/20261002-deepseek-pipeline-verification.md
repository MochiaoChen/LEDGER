## 真实样例的内容质量结论：未达标

当前仓库新版 `status` 对同一工作区只认定 **5/8 闸门**：财务抽取、分析框架、经营数据、估值假设、估值运行通过；文稿、排版、交付说明未通过。原 `guard` 对数字通过，但正文仍出现：

- “程序未触发 EPS 质量预警”“程序归因”“模型状态 `senior-review-ready` / `screen-grade`”等自我解释，且两个模型状态互相矛盾；
- “不是……而是……”“而非”等用户明确要求避免的冗余否定句式；
- “销量是唯一可靠增量”“供给约束在投产节奏而非订单”“现金流与股东回报构成估值的下限”“境外占比提升是确定的正向变量”等未经充分证据支持的绝对化判断；
- 部分利润与分部销量对比涉及口径不一致风险，不能因数值 guard 通过就视为投资推断成立。

已新增可复现的文稿最低标准检查（内部流程话术、冗余否定句式、占位符、无依据的“估值下限”措辞），因此上述稿件现在被闸门明确拦下。这个检查是**必要但不充分**条件：不能自动证明因果推断、行业分母、会计口径、评级的正确性。当前样例及临时 PDF 不可发给负责人作为正式研报，也未执行 `collect`、commit、push 或 PR。

## 已知边界

1. 工作区是内容隔离，不是操作系统级沙箱；报告排版脚本虽不继承 API Key，但运行前仍应审查模型生成的脚本。现有 Claude/Codex 路径也允许公司编排脚本。
2. 本轮未测 Windows 真机。已生成 `py.cmd`，源码和测试覆盖平台分支；部署时应在 Windows 本机重新 `build`，并跑完整端到端测评。
3. 真实样例只覆盖宁德时代，招商轮船尚无同标准完整运行。8 个闸门和客观计数通过也不足以证明研究判断质量；下一轮应先修正文稿论证与用语，再看排版和 Windows 真机结果。
