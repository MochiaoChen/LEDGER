# 联网调研：先搜集、后分析

年报只讲公司自己，而且讲的是过去。年报披露之后公司又发了什么定期报告、股价走到哪里、卖方怎么看、
同行值多少倍、行业景气怎么变、最近发生了什么事，这些都要**现查**。你记忆里的行业数据和事件可能过时、记错，
甚至是编造的；即使很确定，也要先检索，查到并登记之后才能写。检索不到的不写。

调研分两次：

1. **资料搜集（阶段 1，研究助理会话）**：在任何分析之前，按下面七个类别把最新信息搜齐，写成资料包。
   后面的框架、预测、估值、文稿都建立在资料包之上。
2. **补充调研（阶段 4，写作会话）**：写完分析框架后，针对资料包没回答、框架又需要的问题补查。

两次都登记进同一个 `research/sources.json`。

---

## 一、资料搜集（阶段 1）

### 1. 先认识公司，再搜

读年报（或招股书）首页、目录和“管理层讨论与分析”的标题，弄清公司卖什么、分哪几块业务、主要竞争对手是谁。
**不做财务抽取、不写分析框架**，那是写作会话的事。

### 2. 七个类别都要覆盖

| category | 搜什么 | 为什么 |
|---|---|---|
| `latest` | 年报（或招股书）之后的定期报告：一季报、半年报、三季报；业绩预告与快报；月度或季度经营数据（销量、订单、交付） | 预测首年要与最新实际业绩衔接，不能只外推年报 |
| `market` | 最近一个交易日收盘价与日期、总市值、近三个月股价走势与区间；新上市公司的发行价与上市日 | 估值的参照；股价是外部数据，必须有来源与日期 |
| `consensus` | 卖方一致预期（收入、净利润、EPS）、评级分布、目标价区间；查不到时登记 `not_found` | 写预期差：我们和市场哪里不同 |
| `peers` | 3～6 家可比公司（同业务、同市场）的股价、市值、市盈率 / EV/EBITDA 等倍数，以及最近财年收入与利润 | 估值交叉验证；数据齐全时写 `peers.csv` 跑可比公司估值 |
| `industry` | 行业规模、增速、渗透率，产品价格或行业价格指数，上游原材料价格，景气指标 | 驱动假设的外部依据 |
| `competition` | 份额与排名、主要对手的产能与价格动作、新进入者 | 竞争格局判断要有出处 |
| `events` | 近三个月的公司公告与新闻：订单、产能、并购、股权变动、分红回购、监管处罚、管理层变动、政策 | 年报之后发生的变化 |

每个类别至少一个问题，问题标 `"phase": "collect"` 和 `"category"`。查不到的标 `not_found`，但要换过两个以上检索词。
闸门要求：七个类别都覆盖、资料搜集累计检索 ≥ 20 次、近 90 天内发布的来源 ≥ 3 个。

### 3. 检索方法

- 每个问题换两三个关键词，中英文都试；WebSearch 找到候选后，**用 WebFetch 打开原文核对数字**。只看搜索摘要就登记，等于没核对。
- 来源优先级：交易所与公司公告（上交所、深交所、巨潮资讯、港交所、公司投资者关系页）> 政府、统计局、行业协会 >
  知名研究机构与行业数据商 > 主流财经媒体。自媒体、论坛、百科、来源不明的转载不用。
- 定期报告优先打开交易所或巨潮资讯的原文；PDF 打不开时，用主流财经媒体对该报告的报道，并在 `title` 里写明是转述。
- 注意时效：写清发布日期；预测类数据写明是谁在什么时候做的预测。
- 只登记网页原文里出现的数字，**不要自己换算**（百分比、单位、币种都照原文）。

### 4. 写资料包 `research/dossier.md`

资料包是给写作会话看的简报，每条事实句末带 `[S编号]`，按下面的结构写：

```markdown
# <公司> 资料包（截至 <今天日期>）

## 一句话：年报之后最重要的变化
## 最新业绩（latest）
- 期间、收入、归母净利润、同比；管理层对下半年或全年的表述 [S1]
- 与年报相比的变化：……
## 行情（market）
## 卖方观点（consensus）
## 可比公司（peers）
| 公司 | 代码 | 股价 | 市值 | PE | EV/EBITDA | 数据日期 | 来源 |
## 行业（industry）
## 竞争（competition）
## 近期事件（events）
## 对预测与估值的含义
- 哪些假设要用最新数据校准（例如：上半年净利润已达 X，全年预测要与之衔接）
- 哪些信息与年报叙述矛盾，需要写作会话注意
## 没查到的
```

“对预测与估值的含义”只写方向和需要校准的地方，不替写作会话下结论、不起草假设数值。

### 5. 可比公司表 `research/peers.csv`（可选）

可比公司的数据都查到且已登记时，按 `data/samples/peers.csv` 的列写 `research/peers.csv`：金额单位百万元，股本百万股，
股价元；`market_data_date` 写数据日期；`source_name` 写“<发布方> [S编号]”；`inclusion_rationale` 写入选理由。
缺数据的格子留空，不要估。写了这张表，估值命令要带 `--peers <work>/research/peers.csv`（闸门会检查）。

## 二、补充调研（阶段 4）

写完 framework.md 后，在里面写 `## 外部调研清单`：从投资主线和驱动清单倒推，列出资料包**没回答**、但影响结论的问题，
每个问题写清楚要什么数据、为什么要。逐题检索，问题标 `"phase": "followup"`（可不写 category），追加进同一个 sources.json。
闸门要求至少 3 个补充问题，且 sources.json 晚于 framework.md。

查不到就标 `not_found`，并在 framework.md 里把相关分析改成情景处理或删掉；如果它影响核心结论，写进 review.md。

## 三、登记格式 `research/sources.json`

```json
{
  "questions": [
    {"id": "Q1", "phase": "collect", "category": "latest", "question": "2026 年半年报业绩", "status": "found",
     "queries": ["<公司> 2026 半年报 归母净利润", "<公司> 半年度报告 2026"], "sources": ["S1"]},
    {"id": "Q2", "phase": "collect", "category": "consensus", "question": "卖方一致预期", "status": "not_found",
     "queries": ["<公司> 一致预期 2026", "<公司> 目标价 评级"], "sources": []},
    {"id": "Q9", "phase": "followup", "question": "2026 年全球油轮运力增速", "status": "found",
     "queries": ["2026 tanker fleet growth forecast"], "sources": ["S7"]}
  ],
  "sources": [
    {"id": "S1", "title": "<网页标题>", "publisher": "<发布方>", "url": "https://...",
     "published": "2026-08-30", "accessed": "2026-10-03",
     "facts": [{"quote": "<原文中包含该数字的一句话，≤120 字>", "value": 69.6, "unit": "亿元",
                "label": "2026 年上半年归母净利润"}]}
  ]
}
```

- `quote` 摘自原文、包含 `value` 的原样写法；`verify-sources` 会检查数字是否出现在摘句里。
- 定性判断（排名、“龙头”、政策内容）也登记成 fact，`value` 可省略，`quote` 写原文。
- `published` 必填（能查到的话）：资料搜集闸门按它统计近 90 天的来源。
- 检查：`PY -m finagent verify-sources --sources <work>/research/sources.json`，到 `ok: true`。

## 四、怎么用

- 正文引用外部内容时句末加 `[S编号]`；guard 会把 sources.json 里的数字当作出处，但要求句子带对应编号，
  “龙头”“领先”“市场份额”之类的判断没有编号也会被拦下。
- **估值假设要用资料包**：预测首年与年报之后的最新业绩衔接，增速、价格、利润率的依据引用 `[S编号]`；闸门要求假设文件里至少有一处引用。
- 年报之后的最新进展要写进正文（业绩回顾或核心观点），不能只写年报年度。
- 外部数据画图时，数值从 sources.json 读，`doc.fig(..., src="<发布方> [S编号]，LEDGER 整理")`。
- 附录“外部资料来源”由 reportkit 从 sources.json 自动生成。
