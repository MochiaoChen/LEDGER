# 研报写作规范（分析逻辑 + 文字）

目标是写得像优秀的卖方分析师：先讲清楚这家公司的故事，再用几环关键数据把核心结论推出来，最后落到预测和估值上。
数字规则不变：数字全部来自运行产物或 `research/sources.json`，正文要过 `guard`。

文稿写完后，另有一个没参与写作的会话按 `finagent-review` skill 做复核与可读性改写。
写作时就按本规范写，不要把问题留给复核会话：它只删改措辞，补不了缺失的分析。

## 一、拿不准的内容：自己决定、不写，或者交给人工

| 情况 | 处理 |
|---|---|
| 能根据年报、产物、检索资料自己判断 | 直接写判断，不加“可能”“或许”这类缓冲词，也不解释判断是怎么得来的 |
| 拿不准，也不影响核心结论 | **不写。** 研报不需要面面俱到 |
| 拿不准，但影响核心结论或估值（口径疑问、外部数据互相矛盾、关键假设缺少依据、年报疑似笔误） | 写进 `report/review.md` 复核清单交给人工核对，**正文里不出现** |

正文里出现以下内容就说明这一步没做好：“年报未披露……只能间接验证”“属分析师假设”“需进一步核实”“有待观察”
“数据有限”，以及为模型自己辩护的句子。读者要的是判断，不需要知道你的工作过程。

### 复核清单 review.md 的格式

```markdown
# <公司> 研报复核清单

| # | 事项 | 为什么重要 | 当前处理 | 请核对 |
|---|---|---|---|---|
| 1 | 油轮分部净利润合计高于合并归母净利润 | 影响分部利润占比的表述 | 正文只写分部毛利率，不写占比 | 年报 P20 分部口径是否含少数股东、内部抵销 |
| 2 | 2026 年运价假设取 Clarksons 预测 [S3] | 决定 2026E 利润峰值 | 基准情景按 S3 取值 | 是否有更新的机构预测 |
```

没有需要复核的事项时写“无”。复核清单随交付物一起给用户，不进 PDF。

## 二、核心结论要有几环数据推出来

结论前面至少要有**三环关键数据**，每一环都定量：

```
外部驱动（行业需求/供给/价格，来自检索）→ 公司的量或价（年报经营数据）→ 收入/利润的变化（真值表）→ 预测参数（假设表）
```

例：AI 资本开支增长（检索：四家云厂商单季资本开支）→ 组网架构升级带来的光模块配比提升（检索：GPU 与光模块配比）
→ 公司高速率产品出货与毛利率（年报：分产品收入、毛利率）→ 2026E 收入增速与毛利率假设。

- **重要数据必须定量**：决定结论的驱动（量、价、份额、产能、成本）要写到数字。年报没有就检索；检索不到的，
  在情景设计里体现，并写进 review.md，不要退回到定性描述。
- **次要数据少写**：一个段落三四个数字足够，每个数字都要服务这一段的结论。不要把年报表格逐行念一遍，
  也不要在不重要的科目（营业外收支、小额减值）上展开。
- **结论先行**：小标题和段首句就是结论，后面依次是数据、业务原因、对预测的影响。
- **前后对应**：经营分析里写到的每个变化，都要在盈利预测假设里有对应参数，假设表“依据”列写明对应第几节。

## 三、把故事讲出来

优秀研报读起来像一个逐步展开的故事，图表穿插其中，单靠数字罗列和程序生成的图撑不起来：

1. **从哪里来**：发展历程与关键转折（时间轴图）、业务和产品是什么（产品矩阵表、产业链示意图）。
2. **凭什么赚钱**：壁垒和稀缺性要通过对比说明（与同行或国际可比公司的文字对比表、份额与排名，来自检索）。
3. **现在发生了什么**：年报里最重要的变化，回溯到业务场景。
4. **往哪里去**：行业驱动和公司的应对，再落到量价预测。
5. **值多少钱**：估值、情景与风险。

章节之间靠论证顺序衔接，不写“接下来我们分析……”“下面看……”这类过渡句。每章最后一段落到这一章对投资判断的含义。

现成的非数据图表：`C.timeline`（发展历程、产品推出时间轴）、`C.flow`（产业链、业务模式、收入驱动链条）、
`T.text_table`（同行定性对比、产品矩阵、管理层履历、政策梳理）。用法见 finagent-report 的 `references/sections.md`。

## 四、分析链条：会计指标 → 业务驱动 → 预测假设

每写一个指标，先问“这个数是业务上哪件事造成的”，再问“这件事明年还会不会继续”。

| 会计指标 | 回溯到的业务问题 | 落到哪个预测假设 |
|---|---|---|
| 营业收入 | 量 × 价 × 结构（产品、渠道、地区） | 分部销量、单价增速 |
| 毛利率 | 产品结构、渠道结构、成本（原料、能源、人工、折旧） | 分部毛利率 |
| 费用率 | 投入是否换来量；规模效应 | 费用率路径 |
| 合同负债 / 订单 | 下游打款意愿、在手订单（先行指标） | 下一年收入节奏 |
| 存货 | 战略储备还是产成品积压 | 营运资本天数 |
| 经营现金流 | 回款质量；金融业务等非主业扰动要剥离 | 现金流预测口径 |
| 资本开支 | 产能投放节奏、在建项目 | 资本开支与折旧 |

行业不同，驱动也不同，由 framework.md 推导（见 finagent-report 的 `references/analysis.md`）。

## 五、语言

书面、确定、克制。用户读过的模型初稿，主要问题集中在下面几类（复核会话也按这张表审稿）：

| 类别 | 例句（不要这样写） | 改法 |
|---|---|---|
| 否定对照 | “盈利预测的形状由 2026 年运价高点决定，而不是持续增长”；“收入下降不是需求问题，而是结构调整”；“A 而非 B” | 只写成立的那一半：“2026 年运价高点决定盈利预测的形状：2026E 归母净利润为预测期峰值。” 没人提出过的说法不需要否定 |
| 自证圆场 | “年报未披露分船型 TCE，运价弹性只能由分部利润间接验证”；“与年报的解释一致”；“相互印证”；“属分析师假设” | 不重要就删；重要就写进 review.md；假设放进假设表和表注 |
| 程序口吻 | “程序预测 2026E……”；“模型测算显示”；“经数字护栏核对” | 正文写“我们预计”；方法只在附录“数据来源与方法”出现 |
| 口语与套话 | “不过”“具体来看”“可以看到”“事实上”“换言之”“值得注意的是”“综上所述” | 删掉连接词，段落靠论证顺序衔接 |
| 解释腔 | “……，说明……”；句句以“而”转折 | “说明”全文不超过 2 处，“而”不超过 4 处；归因用“主要系”，影响用“带动”“拖累” |
| 行内标签与页码 | “事实层面”“推论层面”“（观点）”“年报第 20 页” | 用“主要系”“我们认为/预计”区分事实与观点，来源放在图表下方 |
| 无来源的判断 | “公司是全球最大的……”“行业龙头”“市占率领先” | 句中带 [S编号]，或写明“公司披露”；都没有就删 |

**写分析，不要事后解释。** 事后解释是先摆出一个数，再替它找理由、打圆场（“年末利润集中度异常高，不过剔除后……”）。
分析的写法是先给判断，再给支撑它的几环数据：“我们预计 2026 年利润见顶：油轮运价处于高位 [S2]，新船交付集中在
2027 年 [S4]，2026E 归母净利润为预测期峰值。”

改写示例：

- 原句：“不过，年末一个季度的盈利集中度异常高，剔除这一季节性高点后，经常性自由现金流只有……”
  改为：“第四季度贡献全年利润的 X%（extras 比率），主要系资产处置收益集中确认；扣除处置收益后，经常性自由现金流为……”
- 原句：“现金流与库存下移，属分析师假设。若需求或价格不及预期……”
  改为：把假设放进假设表（依据列写明），正文只写：“我们假设 2026 年存货周转天数回落至……，主要依据是……”
- 原句：“程序预测 2026E 归母净利润 133.73 亿元为峰值。”
  改为：“我们预计 2026E 归母净利润 133.73 亿元，为预测期峰值。”

## 六、外部资料的引用

- 年报之外的数字和判断必须来自 `research/sources.json`（检索方法见 finagent-report 的 `references/research.md`），
  句末加 `[S编号]`，排版时变成上标，附录自动列出“外部资料来源”。
- 用外部数据画的图，`doc.fig(..., src="Clarksons [S2]，FinAgent 整理")` 写明来源。
- 外部数字照来源原文写（单位、口径、期间一致），不要自己换算或推算；需要换算的，写成 extras 比率或干脆不用。
- 不同来源说法矛盾时，取更权威、更新的那个，矛盾本身写进 review.md。

## 七、正文之外的说明放在哪里

| 原句类型 | 处理 | 放到哪里 |
|---|---|---|
| 估值假设为草稿、待确认 | 删除 | 交付时告诉用户 |
| 参考股价为外部行情数据、收盘日期 | 改为备注 | 基本数据表下“股价日期：……收盘” |
| 终值占比高、结论对 WACC 敏感 | 改为正常分析 | 估值章节的敏感性分析 |
| 口径简化（EBIT 含财务公司利息、少数股东占比不变、EPS 按期末股本） | 改为备注 | 附录“估值方法说明”（`Config.method_note`） |
| 预测参数取基年实际值 | 改为表注 | 假设表下方 |
| 数据抽取、逐字核对、数字护栏等方法描述 | 改为备注 | 附录“数据来源与方法” |
| 年报没披露、口径存疑、需要人工确认的事项 | 移出正文 | review.md |
| “不构成投资建议” | 只保留一处 | 页脚与免责声明 |
| 图表配色说明（深色为实际、浅色为预测） | 改为图例 | 图内图例 |

## 八、投资建议板块（首页必备）

“● 盈利预测及投资建议”一段：先一句核心逻辑（为什么看好/谨慎），再给预测（未来三年收入、归母净利润、EPS 及增速），
再给估值（当前股价对应 P/E、DCF 每股价值），最后给评级。评级由程序按 `forecast_summary.rating` 的规则给出，
正文只引用，不自己定；附录“投资评级说明”写明规则。

## 九、学习优秀研报

用户提供的优秀研报放在 `references/exemplars/`（PDF 不进仓库时，至少把学习记录写在这里）。写作前读同行业的 2～3 篇，
按“结构、分析链条、句式特点、图表清单”总结后追加到下面的学习记录。只总结方法，不摘抄原文。

## 学习记录

### 东方财富证券《中际旭创（300308）深度研究》（2026-04，30 页，54 个图表）

- **结构**：公司概况（历程、产品、股权与管理层、财务）→ 行业（产品结构与技术演进、产业链、需求驱动）→
  公司竞争力（技术路线、产能、规模、客户）→ 盈利预测与投资建议（分产品假设表）→ 估值（可比公司）→ 风险。
  先讲行业为什么在增长，再讲公司为什么能拿到这部分增长，最后才是数字预测。
- **分析链条**：结论前面有一条可以逐环核对的定量链：四家云厂商单季资本开支（亿美元，逐季）→ 全球算力规模（机构测算）
  → 网络架构升级后的光模块需求倍数（架构对比表）→ 单个 GPU 集群的光模块配比（按集群规模逐档测算）→
  800G 以上产品出货占比（行业数据商预测）→ 公司分产品收入增速与毛利率假设。每一环都有数字和来源，
  核心结论（1.6T 放量带动收入与毛利率提升）是推出来的，不是断言出来的。
- **外部数据**：行业数据商（排名、出货量）、云厂商财报（资本开支）、研究机构白皮书（架构示意）、公司官网（产品图），
  每张图下都写明出处；这类内容我们必须靠检索获得，不能凭记忆。
- **句式**：段首一句结论（常加粗），随后是数据和机制，语气确定；没有“不是……而是”、没有自我辩护，
  也不交代分析过程。描述公司优势时用对比（与同行的产量、销量、营收对比图）代替形容词。
- **图表**：发展历程时间轴、产品矩阵表、应用场景示意、产业链图、技术原理示意图、架构对比表、配比测算表、
  管理层履历表、股权结构图、同行产销量对比、客户集中度与海外收入、行业联盟对比表、分产品盈利预测表、可比公司估值表。
  约一半是非财务数据图表，它们承担了“讲故事”的功能。
