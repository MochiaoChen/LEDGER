# 研报评分标准

`report_v1.json` 是 FinAgent 深度研报的评分标准（默认），用于内部质检与 refine 循环；`report_v0.json` 保留，用于复现 v0 结果。它不进入研报工作区，生成方看不到。

## 怎么来的

两条思路合成四层：

| 层 | 来源 | 判定 | 分值 |
|---|---|---|---|
| L0 硬闸门 | 思路二：流水线必过项 | 程序 | 不计分，任一失败总分封顶 `gate_cap` |
| L1 数据闭合 | 思路二：工作流每次交接的闭合点 | 程序 | 35 |
| L2 分析质量 | 思路一：卖方深度报告关心的核心问题 | Sonnet 盲评 | 45 |
| L3 表达与合规 | 思路一 + finagent-review 的写作要求 | Sonnet 盲评 | 20 |
| N 负向条目 | 研报最伤信誉的三类错误 | Sonnet 盲评 | 命中扣分 |

### 思路一：卖方深度报告在回答哪些问题

本版没有用样本研报，按卖方深度报告的常规体例拆解（模型自身知识），得到下面的问题清单。每个问题对应 L2 的一条或几条条目。
权重按“对结论的影响”分三档：5 分是决定估值的环节，4 分是支撑判断的关键论证，2～3 分是完整性要求。

| 报告部分 | 读者要的答案 | 条目 | 权重理由 |
|---|---|---|---|
| 首页 / 核心观点 | 评级、值多少、两三条理由；为什么值这个价 | L2-01 | 4：读者只读首页时的全部信息 |
| 核心观点 / 市场关注问题 | 我们和市场哪里不同；股价隐含了什么 | L2-02 | 4：没有预期差的报告不构成观点 |
| 公司概况 | 卖什么、卖给谁、靠什么赚钱、优势体现在哪个指标 | L2-03 | 3：背景，必要但不决定结论 |
| 核心驱动 | 外部驱动 → 量价结构 → 收入利润，每环有数字 | L2-04 | 5：预测的骨架 |
| 业绩回顾 | 利润变动归因到科目并量化 | L2-05 | 4：判断盈利质量的依据 |
| 行业 | 供需、周期、竞争格局的数据与出处 | L2-06 | 4：驱动假设的外部依据 |
| 盈利预测 | 关键假设逐项有取值与依据 | L2-07 | 5：估值输入 |
| 估值 | 方法为何适用、参数从何而来 | L2-08 | 3 |
| 估值 | 至少一种独立的交叉验证并解释差异 | L2-09 | 4：单一方法的结论不稳 |
| 估值 | 情景假设差异、价值对什么最敏感 | L2-10 | 3 |
| 风险提示 | 风险落到具体假设，给出影响 | L2-11 | 4：通用风险模板没有信息量 |
| 跟踪 | 可验证的指标、催化剂、失效条件 | L2-12 | 2 |

L3 来自同一份拆解里“读者怎么读”的要求：主线连贯、事实 / 推论 / 观点可分、结论先行、没有机器腔、数字不过密、
图表服务论点、假设与局限透明。

### 思路二：工作流的数据闭合

`年报 → 抽取 → 真值表 → 经营数据 → 预测 → 三表 → DCF → 文稿 → 排版` 的每次交接，上游的数在下游要找得到、对得上：

| 交接 | 条目 |
|---|---|
| 年报 → 真值表 | L1-01 抽取校验 |
| 经营数据 → 预测 | L1-02 分部预测基期闭合、L1-08 预测与历史衔接 |
| 预测 → 三表 → DCF | L0-02 三表勾稽、L0-03 DCF 与三表同口径 |
| DCF → 股权价值 → 每股价值 → 评级 | L1-03 股权价值桥、L1-04 每股价值、L1-05 情景排序、L1-06 敏感性方向、L1-07 终值占比、L0-05 评级 |
| 产物 → 正文 | L0-01 数字护栏、L1-09 正文估值与产物一致 |
| 外部信息 → 正文 | L1-10 外部信息可追溯、L1-11 股价日期与来源 |
| 初稿 → 复核稿 | L1-12 数字锁、L1-13 人工复核清单 |

## 怎么调

改 `report_v1.json` 后重算，不用重跑评审：

```bash
python -m finagent.evaluation score --result eval/results/v0_贵州茅台
```

| 想调的 | 改哪里 |
|---|---|
| 某条的分值 | 条目 `points`（L1 + L2 + L3 合计不必等于 100，但交付门槛按总分算） |
| 负向条目扣多少、封顶多少 | `points`（负数）、`cap`；全部负向合计下限 `negative_floor` |
| 硬闸门失败封顶 | `gate_cap` |
| 交付标准 | `delivery.total`、`delivery.layer_ratio`、`delivery.allow_negative` |
| 程序检查的阈值 | 条目 `params`（终值占比 `max`、预测衔接 `gross_margin_pp` / `growth_pp`） |
| 评审的松紧 | 条目 `criterion` 与 `fail_examples`（改了要重跑评审：`python -m finagent.evaluation run ...`） |
