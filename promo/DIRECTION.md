# 影片方向：LEDGER 宣传片（288 秒，1920×1080，30 fps）

用途：2026 北京市大学生金融人工智能竞赛初赛视频（要求不超过 5 分钟的 MP4）。受众是评审，既要看出技术路线，也要看出这是一个能交付东西的产品。

## 1. 参考拆解

用户没有给参考视频，只提了两个必须有的镜头：**代码出现**、**Agent 运行时在检索**。这两条落在镜头 07（源码）和 05（检索）。

## 2. 产品气质

- **做什么、给谁用**：多 Agent 投研系统。五个无头 Claude Code 会话读年报、搜资料、写研报；确定性 Python 引擎负责定位、校验、全部计算和护栏。用的人是要对数字负责的分析师，用起来的感觉是“冷静、可核对、每一步有据可查”。
- **设计语言来源**：
  - 色板取自计划书 `paper/proposal/ledger.sty`：账簿墨蓝 `#1C2F4A`、印章红 `#A8382A`、账页底色 `#F7F4EC`、栏线 `#C9C2B2`；语义色“确定性程序”蓝 `#2F5E8C`、“模型会话”橙 `#C0782B`、通过绿 `#3D7A4F`。暗场在此基础上提亮（`src/film.css` 的 `--agent-d` 等）。
  - 终端界面 `finagent_tui/app.tcss`（Textual，tokyo-night 主题）原样上镜。
  - 研报 PDF 的版式来自 reportkit 的真实产物（`中际旭创1003.pdf`）。
- **母题**：账页的横线与红色栏线；印章（通过即盖章）；带页码的数字（p.94 · c0351）；`status` 输出的 11 行 `[✓]`；stream-json 事件流；等宽对齐的金额。

## 3. 三个方向

| 方向 | 底色与光 | 字体声音 | 母题来源 | 镜头语言 | 节奏 | 音乐 |
|---|---|---|---|---|---|---|
| A 账页 | 全片纸白 + 墨线，印章红点缀 | 衬线编辑感 | 领域隐喻（账簿、印章） | 平面排版，遮罩擦除 | 发布会式从容 | 钢琴与弦 |
| B 黑盒终端 | 全片黑色舞台 + 荧光 | 等宽技术感 | 界面本身（终端、事件流） | 录屏质感，硬切 | 预告片式紧凑 | 电子脉冲 |

## 4. 选择与理由

选 C。A 讲不出“Agent 在跑”的技术感，B 讲不出“这些数字是算过、核过的”的可信感；这个产品的卖点恰好是两者的分界线，所以把分界线本身做成画面。叙事结构用“完整做完一件真实任务”：跟着中际旭创 2025 年报从一条命令走到 30 页研报，11 道闸门全部通过（真实工作区 `~/finagent-samples/中际旭创_2025`）。

本片专属手法：

1. **明暗双账**：因为系统把“模型会话”和“确定性引擎”严格分开（CLAUDE.md 设计规范 1、10），所以暗场只出现模型在做的事（搜、读、写、改），纸面只出现程序算出和校验过的东西；两者之间一律硬切，不做交叉淡化。
2. **11 道闸门刻度条**：因为 `report_pipeline status` 的输出就是 11 行 `[✓]`，所以片底常驻一条 11 格的刻度，剧情走到哪一道闸门、哪一格盖章，代替章节字卡和进度条；盖章提示条照抄 status 的原文。
3. **真实事件流做运行时镜头**：因为 harness 是无头 Claude Code，它真正的界面就是 stream-json，所以“Agent 在检索”的镜头直接播放研究助理会话的真实记录（29 次 WebSearch、41 次 WebFetch），不画假的聊天界面。
4. **源码当场运行**：因为护栏是几行可读的 Python（`external.find_evidence`），所以让源码带真实行号逐字出现，再对年报第 94 页的真实数字跑三次：原样命中、改一位拒收、只给整数部分拒收，结果都由引擎函数算出。
5. **印章与账页栏线**：因为系统名是 LEDGER（账簿），计划书的色板就叫墨蓝、印章红、账页底色，所以通过用印章，纸面镜头用横线和红色栏线做版式网格。

与本工作区既往影片（`video/`，另一套流程做的版本）的区别：那一支是全片深蓝发光舞台、金色高亮、幻灯片式排版；本片明暗交替、纸面占三分之一时长、用真实产物特写（事件流、源码、年报页、终端界面 SVG）、底部闸门刻度贯穿、音乐按明暗换调式。至少在底色与光、母题来源、镜头语言、转场四个轴上不同。

## 5. 画面规范

- **画幅 / 帧率**：1920×1080，30 fps。暗场底色 `#0B0E14`（质检段落 `#0D0C17`），纸面 `#F7F4EC`。左右安全边 96px；底部 1004～1050px 是闸门刻度条，正文不低于 950px。
- **字号阶梯**：
  - 英文（Maple Mono NF CN，OFL）：字标 236～250px/700；小标 26px/500、字距 0.14em、全大写；数据大字 76～380px/700；代码与终端 22～30px。
  - 中文（Noto Sans SC，OFL）：标题 52～64px/700，开场大字 128～136px/900；说明 27～34px/500；最小 22px。
- **产品界面上镜倍数**：终端界面 SVG 原始字号 20px，按 1.129 倍铺满 1728px 宽（正文约 22.6px）；年报页放大到 1.2 倍并裁到利润表（数字约 23px）；源码 22px 等宽。产品自带暗色主题直接使用。
- **动效语法**：英文小标键入；中文标题逐字升起或遮罩擦出（三种入场轮换）；数字滚动落定；线条从左画出；通过盖章（放大落下 0.2 秒，不回弹）。缓动用 expo.out / power3.inOut，时长 0.2～0.9 秒。**不用**回弹、彩虹渐变、发光光晕、明暗之间的交叉淡化。
- **实现**：视图是镜头内时间的纯函数（`src/kit/time.js`，缓动取自 GSAP），`seek(t)` 任意跳转结果一致；动作时间只写在 `plan.json`，代码用 `act(id)` 读取。
